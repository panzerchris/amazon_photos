# Other Amazon Photos implementations

Source snapshots reviewed on 2026-11-27. “Reported live” below refers to evidence from those projects or their users. The fork’s own [UK live result](authentication.md#uk-live-result-2026-11-27) is tracked separately.

## Independent clients

### Go SDK and CLI by David Weng

The most mature independent candidate in this review. The project had current CI, releases and active changes at the inspected snapshot. Its SDK normalizes the same cookies and resolves explicit US/CA/UK/JP/EU marketplace hosts. The CLI imports browser cookies from a file or prompts without echoing them, checks access before saving an interactive import, and uses private credential storage. It has no session renewal or CSRF-token flow. Its endpoint table explicitly labels UK, Japan and most other non-US routes experimental, and lists the US as live verified. [Source snapshot](https://github.com/thedavidweng/amazon-photos/commit/b33d1089cdbcc0e3cd4770f8de6da3ec3d89cbbf), [region resolution](https://github.com/thedavidweng/amazon-photos/blob/b33d1089cdbcc0e3cd4770f8de6da3ec3d89cbbf/pkg/aphotos/region.go), [credential import](https://github.com/thedavidweng/amazon-photos/blob/b33d1089cdbcc0e3cd4770f8de6da3ec3d89cbbf/internal/cli/auth_login.go), [regional evidence](https://github.com/thedavidweng/amazon-photos/blob/b33d1089cdbcc0e3cd4770f8de6da3ec3d89cbbf/docs/reference/regions.md)

The Go client streams raw files with a media type and known length to `/cdproxy/nodes`, URL-encodes `kind=FILE`, `name` and `parentNodeId`, and supports explicit fail/skip/rename conflict behavior. Skip only succeeds after a matching remote MD5. Downloads can verify both size and MD5 before atomic publication. Reads use bounded retries with `Retry-After`, context cancellation and bounded concurrency. Mutations avoid blind replay. Its mock transport and local HTTP server tests cover the wire protocol, redirects, retries and failure paths. `go test ./...` passed locally on the inspected commit. Its MIT licence is compatible. [Upload](https://github.com/thedavidweng/amazon-photos/blob/b33d1089cdbcc0e3cd4770f8de6da3ec3d89cbbf/pkg/aphotos/upload.go), [download](https://github.com/thedavidweng/amazon-photos/blob/b33d1089cdbcc0e3cd4770f8de6da3ec3d89cbbf/pkg/aphotos/download.go), [client tests](https://github.com/thedavidweng/amazon-photos/blob/b33d1089cdbcc0e3cd4770f8de6da3ec3d89cbbf/pkg/aphotos/client_test.go), [transfer tests](https://github.com/thedavidweng/amazon-photos/blob/b33d1089cdbcc0e3cd4770f8de6da3ec3d89cbbf/pkg/aphotos/transfer_test.go)

Its typed transfer states, cancellable contexts and test coverage make it the stronger off-the-shelf bulk-transfer design. The equivalent UK endpoint still needs a live upload and expiry trial. For a Python library embedded in another process, keep the fork and run the UK acceptance check first. A separate executable could be preferable for a language-independent service if `aphotos` passes that same trial. Its evidence does not yet justify a switch for the specific unattended UK use case.

### Vanessa's Immich synchronizer

Independent Python stdlib implementation. The latest inspected commit was April 2026, with a Docker build and smoke tests. It configures a fixed browser user agent, `session-id`, an `at`/ `ubid` pair, and `x-amzn-sessionid`. It requires manual cookie replacement and restart, with no CSRF or cookie-rotation logic. The cookie names are configurable, but the metadata host is US and the upload host is hardcoded NA. It POSTs multipart `metadata` JSON (including root in `parents`) and a whole-file `content` part to `/cdproxy/nodes`. It tracks Immich asset IDs in a local JSON map, accepts any 409 as already present, has no verified hash comparison, and has no per-request retry/backoff. Its sync deletes remote assets by moving them to trash and its entrypoint repeats runs. Smoke tests exercise multipart formatting and local state. The author reports a US Echo Show setup, with no UK or long-run evidence. MIT. [Commit](https://github.com/vanessa/immich-amazon-sync/commit/6d95d8cfed1f906606df24c7bc7d6b5eadee865d), [request and sync source](https://github.com/vanessa/immich-amazon-sync/blob/6d95d8cfed1f906606df24c7bc7d6b5eadee865d/src/immich_sync.py), [entrypoint](https://github.com/vanessa/immich-amazon-sync/blob/6d95d8cfed1f906606df24c7bc7d6b5eadee865d/entrypoint.sh), [smoke tests](https://github.com/vanessa/immich-amazon-sync/blob/6d95d8cfed1f906606df24c7bc7d6b5eadee865d/tests/test_smoke.py)

It validates the value of the Echo Show use case and supplies an alternate wire format reported on US accounts. This fork keeps raw streaming and checksum verification, which avoids whole-file buffers and false success on filename conflicts.

### Rust Amazon Photo Uploader by entourloop

Independent Rust CLI, active in November 2026. Config scripts import browser cookies, allow manual replacement and retain the selected user agent and upload zone. Requests send `session-id`, `at-acb*`, `ubid-acb*`, `x-acb*` and the session header. The declared `/photos/auth/token` method is unused, and source inspection found no CSRF acquisition or supported renewal flow. It uses `content-{zone}.drive.amazonaws.com/v2/upload` with raw bytes, `x-amzn-file-md5`, file size, parent, rename-on-conflict and a content date derived from EXIF or filesystem data. Folder/album operations use Drive metadata endpoints. A local MD5 catalog prevents re-upload while it remains accurate, and errors can cause a write to be retried. It buffers a whole file and has a small Rust unit test footprint. Source supports a configurable zone, without evidence of UK account success. MIT. [Commit](https://github.com/entourloop/amazon-photo-uploader/commit/47200b0e075b8fe5326238e24bfd8443561118ad), [protocol code](https://github.com/entourloop/amazon-photo-uploader/blob/47200b0e075b8fe5326238e24bfd8443561118ad/src/amzn_photo.rs), [catalog and retry logic](https://github.com/entourloop/amazon-photo-uploader/blob/47200b0e075b8fe5326238e24bfd8443561118ad/src/main.rs), [configuration](https://github.com/entourloop/amazon-photo-uploader/blob/47200b0e075b8fe5326238e24bfd8443561118ad/config_setup.py)

Its v2 request confirms that modern uploads may use a distinct payload contract. The integration branch's explicit v2 mode uses the marketplace upload front door found in the Python forks below. An optional override can select another compatible host. Neither format resolves session renewal.

### Gnzlt standalone Python downloader

November 2026 gist with no package dependency on this library, although it builds on its endpoints. Uses browser cookies, a fixed user agent, a regional suffix override, Drive listing and `contentRedirection`. It checks the remote size and MD5 when present, writes through a temporary file, uses bounded workers, handles 401 and backs off on 429/503. The script can resume from local output. It implements no upload, CSRF exchange or credential renewal, and no automated suite or explicit licence was found in the single-file snapshot. Used as reference evidence for downloads only. [Pinned source](https://gist.github.com/Gnzlt/50b87325c7f0ca51aa495ae2be4e2a27/07894c62f36a6758fb738fac3686cd21c244c89a)

A historical search also found the archived DriveSink. Its original consumer Drive API integration is retired, so its historical authorization flow supplies no current Photos renewal evidence. [Archive and source](https://github.com/caseymrm/drivesink)

## Forks and dependent projects

| **Exloki**, October 2026, MIT fork | The most relevant UK evidence. Read-only video inventory was reported live on one UK account, with browser request headers and a provided cookie export. It validates cookie domain and origin, filters expiries in the CLI loader, disables environment proxies, uses bounded requests and checks sign-in/limit responses. It accepts existing browser CSRF headers in the guarded inventory but does not obtain or renew them. Both legacy and `upload-photos.amazon.co.uk/v2/upload` are exercised with mock transports, and upload/download live coverage is explicitly absent. Its focus is safe inventory and its policy disables library mutations. Useful design reference for TLS, host scoping and distinguishing live evidence from mock coverage. It also supports renaming on collision, album batching and local persisted sync state. Its shared request routine retries some write responses, and no automated suite or UK verification was found. A useful independent check of raw CDProxy formats, conflict hints and folder/album payloads. | **CarstenRI webcam archiver**, May 2026, MIT | Imports `amazon-photos`, then uses a lightweight subclass plus a direct binary CDProxy upload from a background service. The German implementation stores browser cookie values and observed expiries, collects `Set-Cookie` rotations, and pauses attempted uploads after auth failure. It reports short-cookie rotation while the underlying `at-acbde` can still expire. Its periodic probes are unofficial and restricted to the author's German assumptions. Returns a duplicate on any filename 409 and caches one process client. No CSRF handling, automated test suite or UK evidence found. The rotation reports support using the current in-memory cookie jar and making `401` a scheduling signal. [Session code](https://github.com/CarstenRI/webcam-archiver-multi-storage/blob/fea880d9ffe3f4e59f0493444628d99b02db60b7/app/amazon_session.py), [uploader](https://github.com/CarstenRI/webcam-archiver-multi-storage/blob/fea880d9ffe3f4e59f0493444628d99b02db60b7/app/uploader.py) |
| **PowderK**, October 2026, MIT fork | File watcher and container persist the sync database, Parquet and browser profile. Selenium reuses a profile and can obtain cookies after interactive sign-in or ordinary password login when there is no further challenge. It then uses the fork's Amazon client. Device recognition in a browser profile can be useful to a person, but the code provides no supported renew grant and cannot guarantee unattended MFA completion. German-specific login, local dedup/state and little automated verification. The account-password and browser stack were left outside the library.
