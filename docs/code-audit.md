# Library correctness audit

Evidence comes from the original fork tree, source comparisons and repository tests. Live endpoint verification is tracked in [authentication and unattended uploads](authentication.md).

| Severity | Finding and evidence | Resolution or remaining limitation |
| --- | --- | --- |
| High | The constructor selected a region from the first matching suffix, allowed arbitrary `*main` cookies and could form `amazon.None` or the wrong thumbnail host. UK read reports identify the broken suffix. | Explicit stable marketplace aliases, single-market inference and strict HTTPS endpoints preserve UK and both overrides. Selection is covered offline for UK, US, DE and JP. |
| High | Auth failures were retried as generic exceptions, returned as false success or hidden by JSON and missing-value errors. Download and mutation methods could bypass checks. | Central authentication, HTTP, protocol and transport errors, failure propagation through mutations, and synthetic cases for 401, challenges, plain 403 and malformed response paths. |
| High | Async clients disabled TLS certificate verification. Scoped request credentials were at risk when HTTP redirects reused custom headers. Operational log initialization wrote files on import, and error logs included response bodies. | Certificate verification is enabled. Credentials are scoped to configured HTTPS endpoints, redirects are limited to the explicit download path, off-origin download headers are stripped, and import no longer changes global logging or loop policy. Explicit `tmp` snapshots can contain private data. |
| High | Core retry loops caught all exceptions, retried most 4xx and ambiguous POST outcomes, and eventually returned `None`. Rate limiting ignored server instructions. | Finite timeouts and retry count, jitter, numeric or HTTP-date `Retry-After`, and typed terminal failures. Requests after possible upload commit are surfaced as uncertain. Retry sleeps release the concurrency permit. |
| High | Folder queue worker exceptions could leave `Queue.join()` waiting indefinitely. Cancellation values and failures could be discarded, and both folder paths leaked clients. | Context-managed asynchronous request workers with explicit cancellation/join. Folder reads are breadth-first with token or offset pagination. Folder creation validates conflicts and stops on failure. |
| High | Upload accepted any 409 and swallowed failed requests, initialized expensive metadata on a short job and skipped files based on stale cache. The folder-only entry point could not upload one file. | Stream individual or directory uploads, require an ID on success, compare a returned checksum when present, and verify conflicts against live remote metadata. The local cache is informational. A deliberate caller-supplied `md5s` set can still be stale. Reconciliation after ambiguous results remains a caller or opt-in live test responsibility. |
| High | Download swallowed failures, could write server-derived unsafe paths, and could leave truncated final files. | Safe names, status validation, atomic temporary writes, length validation and optional remote MD5 verification before publication. Retry can safely start again with a fresh temporary file. |
| Medium | Search fetched its initial offset twice and ignored small requested limits, Drive's page sizing could omit results, and the trash path used the regular nodes endpoint for subsequent pages. | Shared offset accounting uses one endpoint per listing, deduplicates IDs and honors offsets and limits. The 9,999 cap on Drive nodes and trash persists, and offset pagination cannot guarantee snapshot consistency if the library changes mid-read. Folder tokens are used when returned. |
| Medium | Calendar arithmetic skipped the previous-day result and built invalid dates across month boundaries. Corrupt snapshots yielded `None`, concurrent writes could tear the Parquet file, and missing PyArrow broke clean installations. | Real date offsets, protected atomic cache replacement, usable empty DataFrames, and declared PyArrow. Read errors surface. Use one cache path per account/writer because independent processes can still overwrite each other's snapshots. |
| Medium | Repeated names in nested paths used the first occurrence of the root component. Folder trees mutated the input and could attach descendants before their parent path was built. | Compute relative paths from their actual base, construct trees without changing the input, and track visited IDs. Existing folder conflicts are resolved only from verified metadata. |
| Medium | Favorite, unfavorite, hide and unhide bound the wrong keyword. Album creation and linking could report success after a failed mutation. | Correct node binding and shared request checks. Album creation and membership are two remote requests. Membership failure surfaces, and the album may already exist. No automatically destructive cleanup is used. |
| Medium | Aggregation output created a directory named like a JSON file and ignored the caller's output location. | Both branches write JSON files into `out`, and a falsey `out` disables writing. |
| Medium | Dependency metadata duplicated psutil and relied on implicit NumPy or Parquet dependencies. Loop policy changes and unbounded task creation made integration and tests brittle. | PEP 517/621 packaging, no global loop monkey patches, bounded scheduling and matrix CI. Public methods remain synchronous. Call them from a worker thread in an asyncio application. Cancelling that application thread's await does not cancel the running synchronous operation. |

The protocol can accept a write and lose its reply. Separate processes, concurrent accounts, external writers and eventual search indexing also prevent a strict exactly-once guarantee. Confirmed responses and checksum lookups support reconciliation, while the caller remains responsible for keeping original files until their own success criteria are met.
